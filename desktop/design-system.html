Pierre · Design System

Agent IA — logement social (HLM)

Système light-only à haute densité. On compose toujours avec les primitives shadcn augmentées (src/shared/components/ui/). L'écran Automations en est l'expression canonique. Les tokens dans globals.css sont le détail d'implémentation — jamais la première API.

Intention

Pourquoi ces interfaces

Pierre est un outil métier pour le logement social (HLM) — gestionnaires, agents de terrain, équipes support. Ce n'est pas un chatbot générique : chaque écran sert à superviser, configurer ou valider le travail de l'agent.

Posture fondamentale : l'agent assiste, l'humain décide. Les interfaces montrent l'état, le contexte et la prochaine action — jamais elles ne remplacent le jugement professionnel.

Densité

13px de base, métadonnées à 10px — l'utilisateur traite des volumes.

Layout

Split master/detail · stack de cartes espacées (--auto-desk-gap: 0.75rem) · scroll transparent à gauche.

Surfaces

Échelle crème page/chrome → list-selected → report — 3 niveaux, même famille.

Voix

Inter = machine · Source Serif 4 = parole de l'agent.

Composants

shadcn + Base UI
Hiérarchie : ui/card · ui/button · ui/badge · ui/input … (variants CVA, ref. Automations) → écrans feature → globals.css (tokens). Ne pas réimplémenter boutons, champs, cartes ou modales en HTML/CSS brut.
Primitives augmentées (Automations)
  • Card variant="chrome|selected|report" — stack liste + feuille rapport
  • Button variant="chrome" size="desk" — footer liste
  • Badge size="compact" variant="success|…" — cycles agent
  • Input|Textarea|SelectTrigger variant="desk" — formulaires detail pane
  • Slider — plages numériques (value: number[], ref. range-slider.ts)
Stack technique
  • Headless : @base-ui/react
  • Variantes : CVA dans ui/*.tsx
  • Tokens : globals.css consommés par les variants (détail)
  • Animations UI : motion/react (sélection, expand)
Exceptions autorisées
Motion layoutId sélection, crossfade rapport
Streamdown / Lexical contenu agent markdown / édition
react-resizable-panels split Automations

Reproduire l'ADN « Automations »
Structure & densité
  • Split master/detail : stack Card variant="chrome" à gauche, feuille --auto-surface-report à droite. Gap unique --auto-desk-gap.
  • Densité : 13px de base, métadonnées à 10px, en-têtes ligne 2.5rem calés liste + rapport.
  • Layering crème : 3 surfaces desk page/chrome → list-selected → report — même famille, pas de blanc pur en liste.
  • Scroll liste : cartes à hauteur naturelle (shrink-0), conteneur overflow-y: auto, footer « Nouvelle automatisation » fixe.
  • Sélection : surface relevée via --auto-selection-shadow + layoutId Motion partagé.
Composition & règles
  • Composition : stack Card variant="chrome" + Motion layoutId, detail en Card variant="report".
  • Deux accents : encre = fill CTA · bleu lien = liens & focus uniquement.
  • Deux voix : Inter pour l'UI · .llm-answer (Source Serif 4) pour le contenu agent.
  • États explicites : vide, en cours (Spinner), erreur (Bug), planifié — jamais d'écran muet.
  • Motion obligatoire (motion/react) · light-only, aucun mode sombre.
